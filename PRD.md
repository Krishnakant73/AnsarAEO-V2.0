## 1. TL;DR

**AnsarAEO** is an **AI Search / Answer Engine Optimization (AEO) SaaS**. It helps brands discover whether AI answer engines (ChatGPT, Perplexity, Gemini, Google AI Overviews, Copilot, Grok) *mention* them for the questions that matter, scores their visibility, audits their website for "AI-citability," generates draft content to close gaps, surfaces competitor intelligence, and attributes AI-search traffic to revenue.

It is an **India-first** product: INR pricing, multilingual prompts (all 22 scheduled Indian languages + English), and WhatsApp integration. It is built as a **real, multi-tenant SaaS**, not a prototype.

## 2. Vision, Problem & Market

### Problem
Search is shifting from blue-links to **answers generated by LLMs**. When a user asks an AI "which face wash should I buy in India?", the AI *decides* which brands to name. Most brands are invisible in these answers — and have no tool to (a) measure that, (b) understand why, or (c) fix it.

### Vision
Make every Indian brand **discoverable, cited, and trusted by AI answer engines** — with the same rigor SEO gave to Google.

### Why now
AI Overviews, ChatGPT search, and Perplexity are becoming default discovery surfaces, especially for consideration-stage, high-intent queries. Traditional SEO tooling does not measure or optimize for *citation by models*.

## 5. Architecture

### 5.1 Domain model (mental model for everything)
- **Organizations** own **Brands**. A user is an `org_member` (auto-created on signup by the `handle_new_user()` trigger).
- **Prompts** = the specific questions a brand wants to be mentioned for (e.g. "best face wash in India"), language-tagged, belong to a brand.
- **Engines** = AI answer engines (`chatgpt`, `perplexity`, `gemini`, `google_ai_overview`, `grok`, `copilot`).
- **Visibility runs** = one prompt evaluated against each *active* engine; stores `raw_response`, `brand_mentioned`, `brand_position`, `sentiment`, `competitor_mentions`, `citations`, `mention_verification`.
- **Citations** = URLs cited, flagged own-domain / competitor-domain, plus `source_quality` (0–100 deterministic proxy) and `is_trusted_source`.
- **Prompts** carry an `intent` column (canonical funnel-stage taxonomy: awareness / comparison / best_choice / problem_solving / local_intent / purchase_intent / branded).
- **Visibility runs** also store `recommendation_alignment` (aligned / misaligned / neutral — LLM-judged proxy from the classification pass).
- **Geo metric snapshots/events** = persisted, normalized metric bundles (`geo_metric_snapshots`) + anomaly/delta events (`geo_metric_events`), computed nightly from recorded runs/citations (never estimated).
- Plus: `competitors`, `content_items` (Content Studio drafts), `integrations`, `site_audits`, `payments`/`plan_limits`, `agent_conversations`/`agent_messages`, `automation_actions`.

### 5.2 Core pipeline — `src/lib/visibility-engine.ts`
`runVisibilityCheck(promptId)`:
1. Load prompt + brand + confirmed competitors + active engines (service client).
2. For each engine, call the LLM via the `ENGINE_CALLERS` registry (a `Record<engineName, callerFn>` — add engines here, keep name synced with `engines.name`).
3. Cheap `gpt-4o-mini` classification pass (JSON mode) → `brand_mentioned` / `sentiment` / `competitor_mentions` / `cited_urls`.
4. **Reconcile** LLM self-report against a **deterministic** text/fuzzy match (`src/lib/mention-matcher.ts`). On disagreement the deterministic result wins for literal name presence; LLM stays authoritative for sentiment/position. The agreement is logged in `mention_verification`, not silently resolved.
5. Insert a `visibility_runs` row + `citations`.

`google_ai_overview` is **not** the Gemini chatbot — it scrapes real Google AI Overview boxes via DataForSEO and **skips** (rather than storing a misleading "0% mentioned") when no AI Overview triggers.

Invoked three ways: manual `POST /api/visibility-check`, nightly cron `/api/cron/nightly-runs`, and `/api/content/generate` flows.

### 5.3 Supabase clients (know which one)
- `createClient()` (server) — request cookies, respects RLS, scoped to logged-in user.
- `createClient()` (browser, `@/lib/supabase/client.ts`) — for `"use client"` components.
- `createServiceClient()` — **service-role, bypasses RLS**, server-only (cron, reports, visibility runs). Never imported into a client component.

### 5.4 Multi-brand + auth
- Selected brand remembered in `selected_brand_id` cookie, resolved by `getSelectedBrand()`; falls back to first brand.
- `src/proxy.ts` refreshes the Supabase session and **redirects unauthenticated users away from `/dashboard/*`** (matcher `/dashboard/:path*`).
- Dashboard layout also `redirect("/login")` if no user.

### 5.5 Engine / library map (all read before touching)
Full list in `CLAUDE.md`; highlights: `visibility-engine` (classification now also returns `recommendation_alignment`; citation insert computes `source_quality` + `is_trusted_source`), `site-audit-engine` (12-bot crawlability, citability score, grade/scorecard, hidden-text detection, AI fix snippets, entity/sameAs, agent-readiness), `ai-index-generator` (llms.txt/robots/JSON-LD/intent pages/aeo.json/entity.json), `content-engine` (drafts with `[ADD …]` placeholders), `agent-context` (grounded chat), `social-signals`, `content-gap`, `content-optimizer`, `pdp-generator`, `visibility-consistency`, `prompt-suite`, `fanout-coverage`, `answer-blocks`, `geo-linter`, `llms-txt-validator`, `schema-for-ai`, `internal-link-graph`, `token-bloat`, `price-factcheck`, `gsc`, `robots-validator`, `header-link-graph`, `topical-coverage`, `competitor-intel` (battlecards + opportunities + **"why they win"** reasons), `gbp-audit`, `revenue-attribution`, `crypto`, `whatsapp`, `razorpay` — **and the metrics layer:** `geo-metrics` (pure deterministic engine: `computeGeoMetrics` → visibility/citation rate & share, avg rank, model divergence, trend velocity, recommendation quality, sentiment, per-engine + per-intent breakdowns), `citation-quality` (deterministic `source_quality` proxy + co-citation), `intent` (taxonomy), `snapshots` (persisted snapshot + anomaly events), `outcome` (GA4/Shopify revenue KPI).

### 6.3 Principles
- **Honesty by design:** generation-only features never fabricate data; drafts carry explicit `[ADD …]` placeholders for owner-only facts (prices, stats, names, credentials). The shared PDF report only includes *persisted* datasets — it deliberately omits stateless features rather than inventing sections.
- **Deterministic over opinion:** parsers/linters use measurable text/HTML properties (no LLM, no API key, reproducible) — e.g. `geo-linter`, `llms-txt-validator`, `robots-validator`, `token-bloat`.
- **Failure isolation:** visibility runs use `Promise.allSettled` so one missing API key returns partial results; `grok`/`copilot` skip when keys absent.

## 7. Feature Catalog

### 7.0 Visibility Metrics Layer (geo-metrics) — *the core decision system*
This layer turns raw `visibility_runs` + `citations` into normalized, decision-ready scores. It re-centers the product on **visibility → quality → outcome**.
- **Metric engine** (`src/lib/geo-metrics.ts`, pure & unit-tested) — `computeGeoMetrics` derives: `visibility_rate` (mentioned/total), `citation_rate` (cited, not just mentioned), `citation_share` (brand's share of all citations vs competitors), `avg_rank` (mean position when mentioned), `sentiment_score` (pos/neu/neg composite), `model_divergence` (std-dev of per-engine visibility rates), `recommendation_quality` (aligned/mentioned), `trend_velocity` (current-vs-prior window), plus `per_engine` and `by_intent` breakdowns. All percentages round to integers; null when there's no denominator (never faked).
- **Prompt intent taxonomy** (`src/lib/intent.ts`) — 7 canonical intents (awareness / comparison / best_choice / problem_solving / local_intent / purchase_intent / branded) mapped from starter-prompt groups + text inference, stored on `prompts.intent`; drives funnel-stage KPI breakdowns.
- **Citation / source-quality scoring** (`src/lib/citation-quality.ts`) — **deterministic proxy**, `source_quality` 0–100 + `is_trusted_source`, from a curated authority list (Wikipedia, WHO, Statista, major Indian/trusted press, etc.), trusted TLDs (`.gov`/`.edu`/`.org`/`.ac.in`…), and own-vs-competitor context. **Labeled a proxy, not true domain authority** (see §10). Also computes co-citation (does the brand appear alongside trusted sources in the same answer).
- **Real domain authority (DataForSEO)** — `src/lib/domain-authority.ts` enriches cited domains with **DataForSEO `domain_rank`** (0–100, computed from their backlink index — a real, externally-computed authority signal that *complements* the `source_quality` proxy). Lookups are cached in `domain_authority` and refreshed incrementally (bounded batch) by the nightly cron; `citations.authority_score`/`authority_source` carry the value when present and stay NULL otherwise. `authority_source` is **always labeled** (e.g. `dataforseo_domain_rank`) so the UI never implies it's Google's own DA. Degrades gracefully when `DATAFORSEO_LOGIN`/`DATAFORSEO_PASSWORD` are absent (migration_014).
- **Recommendation alignment** — the visibility-engine classifier now also judges whether the brand is described *correctly for the use case* (aligned/misaligned/neutral) in the same LLM pass, persisted to `visibility_runs.recommendation_alignment`. Clearly an LLM-judged proxy.
- **Persisted snapshots + events** (`src/lib/snapshots.ts`, `migration_012`) — `geo_metric_snapshots` (windowed metric bundle) + `geo_metric_events` (delta/anomaly). Computed nightly from recorded data only.
- **Competitor "why they win"** (`/api/competitors/why`) — per-prompt reasons a competitor beats you (recommended when you're absent, outranks you, cited alongside you). Read from real runs/citations.
- **Outcome KPI** (`src/lib/outcome.ts`) — AI-referral sessions + assisted revenue from connected GA4/Shopify integrations, shown on the dashboard **only when integrations exist** (never fabricated).
- **PDF section** — the shared PDF report now includes a "Visibility Metrics" section sourced from the persisted snapshot (persisted-only, honest).

### 7.1 Visibility & Tracking
- **Visibility Engine** — run a prompt across all active engines; measure mention, position, sentiment, recommendation alignment; reconcile vs deterministic match.
- **Mention Consistency** — re-run a prompt N times per engine; compute a *mention-stability* score (how reliably cited). Stateless.
- **Blind Discovery / Organic Recall** — unbranded category question N times; measure if the brand surfaces *unprompted* + which competitors appear instead. Stateless.
- **Prompt Suite** — generate an intent-grouped monitoring matrix (recommend/compare/define/tutorial/alternative), one-click add as tracked prompts; each prompt tagged with its canonical intent. Generation-only.

### 7.2 Site & Content Optimization
- **Site Audit** — robots.txt 12-bot crawlability, sitemap, schema/JSON-LD, headings/question-headings, OG/meta, JS-render risk, BLUF, E-E-A-T, security headers, performance, hidden-text/prompt-injection detection, entity/sameAs, AI-provenance, agent-readiness/WebMCP. Returns scored `AuditResult` + letter **grade** + per-category **scorecard** + AI fix snippets. Persisted.
- **GEO Content Linter** — deterministic, LLM-free lint of a URL/pasted text for ciability signals. Stateless.
- **Content Optimizer** — rewrite existing content to be more citable; GEO/AEO/Readability scores + honest rank-gain proxy. Generation-only.
- **Content Studio** — generates a DRAFT article with `[ADD …]` placeholders; `eeat_checklist` blocks *approval* until a human fills specifics. Persisted.
- **Answer Block Generator** — quotable answer blocks (paragraph/BLUF, list, comparison table, HowTo, FAQ) + JSON-LD stub. DRAFT with placeholders. Generation-only.
- **PDP Generator** — product-page GEO optimization: schema.org Product JSON-LD + copy from URL/JSON with an evidence ledger. Generation-only.
- **AI Intent Pages + Retrieval Vocabulary** — source-backed pages stating when an AI should recommend the brand; deterministic term expansions. Generation-only.
- **AI Index Generator** — builds `llms.txt`, robots AI-welcome block, Organization JSON-LD, `SEO.md`, `ai.txt`/`llm.txt`, `aeo.json` (atomic Q/A facts), `entity.json` (sameAs graph). Generation-only.
- **llms.txt Validator** — deterministic llmstxt.org grammar check + discovery-header checks. Stateless.
- **Schema-for-AI Generator** — templates for 7 AEO schema.org types + dependency-free JSON-LD validator. Generation-only.

### 7.3 Competitive Intelligence
- **Competitor Intelligence** — Citation Opportunities (domains cited where a competitor is mentioned but you aren't, with outreach brief) + Battlecards (share-of-voice + sentiment + side-by-side) + **"Why they win"** (per-prompt reasons a competitor beats you: you're absent, they outrank you, or they're cited alongside you). Reads persisted data.
- **Topical Coverage Gaps** — crawl your sitemap + each competitor's; report topics competitors cover that you lack (priority = how many share them) + your unique strengths. Stateless.
- **Internal Link Graph + Cannibalization** — crawl sitemap (cap 50), compute orphans/dead-ends/hubs/broken links/TF-IDF suggestions/keyword cannibalization. Analysis-only.
- **Header & Link Graph** — per-page HTTP response headers + `Link:` graph; canonical presence, llms.txt/ai.txt advertisement, `X-Robots-Tag` AI-blocking. Stateless.
- **Citation Decay / Trend** — monthly own-domain vs competitor-domain share + per-domain momentum. From persisted `citations`.

### 7.4 Discovery & Analysis
- **Query Fan-Out Coverage** — given a topic (+ optional page), generate sub-questions an AI fans out into; judge covered/partial/missing with evidence. Stateless.
- **Token Bloat / AI-Crawler Efficiency** — deterministic per-page token/byte measurement + bloat flags; ratios exact, absolute counts approximate. Stateless.
- **Ecommerce Price/Stock Fact-Check** — sample engines with a buying question; fact-check the AI's price/stock for your brand vs true feed + rank vs competing retailers. Stateless.
- **Brand Signals / Social Listening** — Reddit (public JSON, no key) + optional YouTube; sentiment classification. Point-in-time, not persisted.
- **GSC Index Monitor** — user-owned Search Console OAuth; URL Inspection index status, on-demand reindex, de-index detection. Persisted snapshot.
- **Robots.txt Validator** — deterministic, spec-accurate (group resolution, `*`/`$` wildcards, longest-rule-wins). Stateless.

### 7.6 Metric definitions, formulas & rigor

To read as a *measurement system* executives trust, every KPI has one definition, one formula, and explicit sample-size + edge-case rules. All live in `src/lib/geo-metrics.ts` (`computeGeoMetrics`, pure & unit-tested).

**Core definitions**
- **Mention** = t
he brand name is present in the engine's answer. The deterministic substring/fuzzy match (`mention-matcher.ts`) wins over the LLM self-report for literal presence; the split is logged in `mention_verification`. A mention is *literal presence*, not endorsement.
- **Citation** = a `citations` row for the run — a URL the engine linked/referenced, flagged own-domain / competitor-domain / third-party. You can be *cited without being mentioned* and *mentioned without being cited*.
- **Recommendation** = the brand is framed as a correct answer for the prompt's use case (`recommendation_alignment = aligned`). A *neutral* mention names the brand but doesn't endorse; a *misaligned* mention frames it negatively or for the wrong use case. Recommendation is LLM-judged (proxy); **sentiment is separate** (tone of the mention, not whether it endorses).

**Formulas** (all percentages round to integer; `null` when denominator = 0 — never faked)

| Metric | Formula | Window |
|---|---|---|
| `visibility_rate` | mentionedRuns / totalRuns × 100 | current |
| `citation_rate` | runsWithOwnCitation / totalRuns × 100 | current |
| `citation_share` | ownCitations / totalCitations × 100 | current |
| `avg_rank` | mean(`brand_position` over mentioned runs with non-null position) | current |
| `sentiment_score` | (Σ pos +1, neu 0, neg −1)/n, normalized to 0–100 | current |
| `model_divergence` | population std-dev of per-engine `visibility_rate` | current |
| `recommendation_quality` | alignedRuns / mentionedRuns × 100 | current |
| `trend_velocity` | currentWindow metric − priorWindow metric (pp) | 7d vs prev 7d |
| `per_engine` | per-engine `visibility_rate` / `citation_share` / `avg_rank` | current |
| `by_intent` | per-intent `visibility_rate` / `citation_rate` (funnel-stage) | current |

**Sample-size rules**
- Any metric computed over fewer than **N=5** runs in the window still shows the number but is flagged "low sample" in the UI.
- `trend_velocity` requires a non-empty prior window or it reads `null` (no estimate).
- `model_divergence` needs ≥2 active engines with ≥1 run each; otherwise `null`.
- `avg_rank` needs ≥1 mentioned run with a non-null position; otherwise "—".

**Engine-by-engine reliability notes**
- `chatgpt`, `perplexity`, `gemini`, `grok`, `copilot` run via the LLM `ENGINE_CALLERS` registry; `google_ai_overview` is a **SERP scrape** (DataForSEO) and *skips* silently when a query triggers no AI Overview (never stores a misleading 0%).
- `grok`/`copilot` skip when their API keys are absent (`Promise.allSettled` isolation) → partial results, not failure.
- Per-engine rates use only runs that actually executed for that engine.

**Missing / contradictory engine output**
- A run with no `raw_response` (engine error/timeout) is excluded from that engine's numerator **and** denominator — it never counts as a "not mentioned."
- LLM self-report vs deterministic mention disagree → deterministic wins for literal presence; LLM keeps sentiment/position; the split is stored in `mention_verification` and surfaced as a data-quality signal, never silently resolved.

**Alert thresholds (planned — see §7.7)**
- Defaults: `citation_rate` drop ≥15pp vs prior 7d; `avg_rank` worsen by ≥2 positions; competitor `citation_share` spike ≥10pp; any new `anomaly` event in `geo_metric_events`. All user-configurable.

#### 9.1.2 MCP Server (`mcp-server/`)

A **standalone** Stdio MCP (Model Context Protocol) server — excluded from the Next.js app build on purpose (it has its own `package.json`, `tsconfig.json` NodeNext, and `README.md`). Lets an MCP-aware client (Claude Code via `.mcp.json`) query the live product data directly.

- **Transport:** `StdioServerTransport` (spawned by the client; `.mcp.json` registers it as `node mcp-server/dist/index.js`).
- **Auth:** lazily builds a **service-role** Supabase client from `NEXT_PUBLIC_SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` only when a tool is called — so the server boots even if env vars are missing (the tool returns a clear error instead of crashing at startup). Bypasses RLS by design (trusted, server-side).
- **Tools (3):**

  | Tool | Input | What it returns | Purpose |
  |---|---|---|---|
  | `aeo_list_brands` | — | all brands: `id, name, domain, org_id` | Inventory/overview of the workspace |
  | `aeo_visibility_summary` | `brandId` | `{ totalRuns, mentionRatePct }` across all that brand's visibility runs | Quick "is this brand cited?" health metric |
  | `aeo_list_competitors` | `brandId` | confirmed competitors: `id, name, domain, confirmed` | Surface a brand's tracked competitive set |

- **Build/run:** `cd mcp-server && npm install && npm run build`, then it's usable wherever `.mcp.json` is registered. Not part of `npm run build` for the app.

#### 9.1.3 CI / Automation Pipeline

- **`.github/workflows/ci.yml`** — GitHub Actions on every push/PR: `setup-node 20` → `npm ci` → **typecheck** (`tsc --noEmit`) → **lint** (`eslint .` — native flat config, `eslint.config.mjs`) → **test** (`vitest run`) → **build** (`next build`). Concurrency group `ci-${{ github.ref }}` cancels stale runs. **Purpose:** catch type/lint/test regressions before merge; gate shipping on a green build.
- **`.github/dependabot.yml`** — weekly `npm` + `github-actions` version bumps. **Purpose:** keep dependencies patched without manual chore.
- **`vitest.config.ts`** — scopes test discovery to `src/**/*.test.ts` and excludes `node_modules`, `.next`, `.claude`, `mcp-server`, `dist`. **Purpose:** stop the test runner from scanning skill/agent files (which import `bun:test`) and producing phantom failures.

## 10. Honest Gaps & Known Limitations

From the project's own documentation (these are *real* limitations, not invented TODOs):
- **No automated API-route integration tests** — only lib-level unit tests exist.
- **No monitoring/observability** (Sentry/PostHog) historically — partially addressed by `monitoring.ts` (webhook sink only).
- **No queue-based job runner** — nightly/weekly crons loop sequentially; fine at low scale.
- **WhatsApp approval webhook** matches the most-recent pending action (now org-scoped); reference-code precision is best-effort via `details.reference_code`.
- **Revenue attribution** joins GA4 + Shopify by date only (correlation, not causal).
- **Site-audit robots.txt parser** is a simplified regex (the dedicated Robots.txt Validator covers edge cases).
- **Marketplace visibility** (Amazon Rufus, Flipkart AI) — no public APIs.
- **WordPress auto-publish** for approved drafts — approve flow exists, publish integration does not.
- **Reddit signals** are rate-limited/unauthenticated; YouTube needs a key; neither persisted.
- **Source-quality is a deterministic *proxy*, not true domain authority** (`src/lib/citation-quality.ts`). It is built only from signals we actually have at citation time (curated trusted-domain list, trusted TLDs, own-vs-competitor context). A real authority signal is now available as a **complement** via DataForSEO `domain_rank` (`src/lib/domain-authority.ts`, migration_014) — cached per domain, labeled `dataforseo_domain_rank`, and surfaced in the Citations table. It still is *not* Google's own DA (no third party has that); if `DATAFORSEO_LOGIN`/`DATAFORSEO_PASSWORD` are absent, `authority_score` stays null and the deterministic proxy remains the honest default. Both are clearly distinguished in the UI ("DA 74" = real feed vs "~55 proxy").
- **Geo metric snapshots are nightly**, not live-streamed. Current-window KPIs on the dashboard are computed **real-time** from the latest recorded runs/citations (the page is `force-dynamic`, no cache); trend velocity + the PDF "Visibility Metrics" section read the nightly snapshot. Data freshness ultimately depends on when a visibility run last executed (manual or the nightly cron).
- **Recommendation quality** is an LLM-judged proxy (alignment from the classification pass), clearly labeled.
- **MCP server** requires its own `npm install && npm run build` (excluded from the app build by design).
